## 一、项目整体介绍

### 这个项目是做什么的？

简单说，就是一个**公司人事管理系统**，帮公司管三件事：
1. **员工信息** - 谁在哪个部门，工资多少
2. **考勤打卡** - 谁迟到了，谁请假了
3. **工资核算** - 自动算每个人该发多少工资

### 项目长什么样？

```
用户打开浏览器 → 看到网页界面 → 操作数据 → 数据存在数据库里
     ↑                    ↓
   前端(Vue)         后端(Spring Boot)
```

- **前端**：你看到的网页，按钮、表格、图表
- **后端**：藏在后面的程序，处理数据、算工资
- **数据库**：存数据的地方，员工信息、考勤记录都存在这

### 为什么要分前后端？

就像餐厅：
- **前端 = 服务员**：接待顾客，把菜单给顾客，把订单传给厨房
- **后端 = 厨师**：在厨房做菜，做好了给服务员端出去
- **数据库 = 仓库**：存食材（数据）

分开的好处：服务员和厨师可以各自升级，互不影响。

## 三、后端技术

### 1. Spring Boot - 后端框架

**是什么？**
Java语言最流行的后端框架，帮你快速搭建网站后台。

**类比：**
就像精装房。Spring Boot把水电、装修都做好了，你直接拎包入住，不用自己盖房子。

**项目中怎么用？**
- 接收前端的请求（比如"生成工资单"）
- 处理业务逻辑（算每个人的工资）
- 把结果返回给前端

### 2. Spring Security + JWT - 安全登录

**是什么？**
- **Spring Security**：管权限的，谁能看什么，谁不能看什么
- **JWT**：登录凭证，登录成功后给你一个"通行证"，以后每次请求都带着

**类比：**
- Spring Security = 小区保安，检查你有没有权限进小区
- JWT = 门禁卡，刷卡进门，卡过期了就要重新办

**项目中怎么用？**
- 管理员能看所有数据，员工只能看自己的
- 登录成功后返回token，存在浏览器里
- 每次请求都带上token，后端验证你是谁

### 3. MyBatis-Plus - 数据库操作工具

**是什么？**
帮你操作数据库的工具，不用写复杂的SQL语句。

**类比：**
就像智能仓库管理员。你说"给我找所有技术部的员工"，它自动去仓库找，不用你自己一个个翻箱子。

**项目中怎么用？**
- 查员工列表、新增员工、修改员工信息
- 自动生成常用的增删改查，不用写SQL

### 4. Spring AOP - 面向切面编程

**是什么？**
在不修改原代码的情况下，给方法加额外功能。

**类比：**
就像给所有快递包裹自动贴快递单。不用每个包裹都手动贴，在传送带上装一个自动贴单机，所有包裹经过时自动贴。

**项目中怎么用？**
- 操作日志：所有新增/修改/删除操作自动记录日志
- 不用在每个方法里都写"记录日志"的代码

### 5. Maven - 项目管理工具

**是什么？**
管理Java项目依赖（第三方工具包）的工具。

**类比：**
就像手机的应用商店。需要什么工具，告诉Maven，它自动帮你下载安装。

**项目中怎么用？**
- pom.xml文件里写需要什么工具
- Maven自动下载Redis、RabbitMQ等工具的代码包

## 五、企业级中间件

> 中间件就是"中间的工具"，帮你解决特定问题，不是业务本身。

### 1. Redis - 缓存

**是什么？**
一个存数据的地方，速度特别快，但数据存在内存里，断电会丢。

**类比：**
就像办公桌。常用的文件放在办公桌上（Redis），随手就能拿到。不常用的放在文件柜（数据库）里，拿的时候慢一点。

**为什么用？**
- 仪表盘数据每次都查数据库太慢
- 存在Redis里，第一次查了存起来，后面直接从Redis拿
- 速度能快10倍以上

**项目中怎么用？**
- 仪表盘统计数据缓存5分钟
- Redis没装也没关系，自动降级用本地缓存

**面试常问：**
- 缓存穿透：查一个不存在的数据，每次都查数据库 → 解决：空值也缓存
- 缓存击穿：热点数据过期，大量请求同时查数据库 → 解决：加锁
- 缓存雪崩：大量数据同时过期 → 解决：过期时间加随机值

### 2. RabbitMQ - 消息队列

**是什么？**
一个"传话"的工具，A把消息放进去，B从里面拿出来处理。

**类比：**
就像快递驿站。你把包裹放驿站（发消息），快递员有空了来取（收消息）。不用你等着快递员来，放下就可以走。

**为什么用？**
- 生成工资单要算很久，用户等着不耐烦
- 把"生成工资单"这个任务放进队列，立刻告诉用户"正在处理"
- 后台慢慢算，算完了通知用户
- 这就叫**异步处理**

**项目中怎么用？**
- 工资单生成支持异步
- 没装RabbitMQ也没关系，自动降级为同步（等着算完）

**核心概念：**
- **生产者**：发消息的人（你放包裹）
- **消费者**：收消息处理的人（快递员取包裹）
- **队列**：存消息的地方（快递驿站）
- **死信队列**：处理失败的消息放这（问题包裹）

### 3. XXL-Job - 分布式任务调度

**是什么？**
定时执行任务的工具，比如"每月1号自动生成工资单"。

**类比：**
就像闹钟。设定好时间，到点了自动响（执行任务）。

**为什么用？**
- 每月1号要生成上月工资单，不能每次手动点
- 设定定时任务，到点自动执行
- 还能在管理界面看任务执行情况

**项目中怎么用？**
- 每月1号凌晨2点自动生成上月工资单
- 每周日凌晨4点自动备份数据
- 没装XXL-Job也没关系，用Spring自带的定时任务

**和Spring @Scheduled的区别：**
- @Scheduled：简单，单机用，任务写在代码里
- XXL-Job：强大，支持分布式，任务可以在界面上配置，不用改代码

### 4. Knife4j - API文档

**是什么？**
自动生成接口文档的工具，不用手写文档。

**类比：**
就像餐厅的菜单自动生成器。厨房有什么菜（接口），自动打印成菜单（文档），顾客（前端开发）照着点菜。

**为什么用？**
- 前后端开发时，后端要告诉前端有哪些接口
- 以前要手写文档，改了代码还要改文档，容易忘
- Knife4j自动扫描代码，实时生成文档，永远最新

**项目中怎么用？**
- 启动后访问 http://localhost:8080/doc.html
- 能看到所有接口，还能在线测试

## 七、核心业务逻辑

### 1. 考勤打卡逻辑

```
员工点击打卡 → 系统看时间 → 判断状态
                         ↓
                    9点前 → 正常
                    9点后 → 迟到
                    没打卡 → 缺勤
```

### 2. 薪资核算逻辑（重点！）

```
应发工资 = 基本工资 + 全勤奖 + 加班费 - 迟到扣款 - 缺勤扣款 - 事假扣款

社保扣除 = 基本工资 × 10.5%
公积金扣除 = 基本工资 × 7%

个税 = (应发工资 - 社保 - 公积金 - 专项扣除 - 5000) × 3%
（如果结果≤0，个税为0）

实发工资 = 应发工资 - 社保 - 公积金 - 个税
```

**举例：**
张三基本工资12000，全勤奖300，加班费90，无扣款
- 应发 = 12000 + 300 + 90 = 12390
- 社保 = 12000 × 10.5% = 1260
- 公积金 = 12000 × 7% = 840
- 个税 = (12390 - 1260 - 840 - 0 - 5000) × 3% = 5290 × 3% = 158.70
- 实发 = 12390 - 1260 - 840 - 158.70 = 10131.30

### 3. 权限控制逻辑

三种角色：
| 角色 | 能做什么 |
|------|---------|
| 管理员 | 所有功能 |
| 人事专员 | 员工/考勤/工资/请假审批，不能管部门/租户/系统 |
| 普通员工 | 只能看自己的考勤/工资，能提交请假/加班 |

**三层控制：**
1. **菜单层**：前端不显示没权限的菜单
2. **按钮层**：页面上不显示没权限的按钮
3. **接口层**：后端验证，没权限直接返回403（最关键！）

### 4. 多租户数据隔离

**是什么？**
多个公司用同一套系统，但数据互相看不到。

**类比：**
就像写字楼。很多公司在一栋楼里，但各有各的办公室，门卡只能开自己公司的门。

**怎么实现？**
- 每张表都加一个tenant_id（租户ID）
- 查询时自动加条件 WHERE tenant_id = 当前租户
- 用MyBatis-Plus插件自动加，不用手动写

## 八、面试常问问题

### 项目相关

**Q：介绍一下你的项目？**
A：这是一个基于Spring Boot + Vue的前后端分离考勤薪资管理系统，实现了员工管理、考勤打卡、请假审批、薪资自动核算等功能。后端用了Spring Security做权限控制，MyBatis-Plus做数据访问，还集成了Redis缓存、RabbitMQ消息队列、XXL-Job定时任务等企业级中间件。

**Q：项目难点是什么？**
A：薪资核算逻辑比较复杂，要考虑社保、公积金、个税的计算，还要和考勤数据联动。另外多租户数据隔离也是一个难点，用MyBatis-Plus的租户插件实现了无侵入的自动隔离。

**Q：为什么用Redis？**
A：仪表盘数据查询频率高，但数据变化不频繁。用Redis缓存热点数据，减少数据库压力，提升响应速度。同时做了优雅降级，Redis不可用时自动用本地缓存。

**Q：RabbitMQ在项目中怎么用的？**
A：工资单生成比较耗时，用RabbitMQ异步处理。用户点击生成后立刻返回，后台慢慢算，算完了发通知。做了死信队列处理失败消息，还有手动ACK保证消息不丢。

**Q：XXL-Job和Spring @Scheduled的区别？**
A：@Scheduled是Spring自带的，简单但只能单机用，任务写死在代码里。XXL-Job是分布式任务调度，支持集群、任务在界面配置、执行日志可查。项目里两个都支持，没装XXL-Job就用@Scheduled。

### 技术相关

**Q：JWT登录流程？**
A：用户登录 → 后端验证账号密码 → 生成JWT token返回 → 前端存在localStorage → 以后每次请求Header带token → 后端过滤器验证token → 验证通过放行。

**Q：MyBatis-Plus的租户插件原理？**
A：MyBatis-Plus在SQL执行前拦截，自动在WHERE条件后加tenant_id = 当前租户ID，INSERT时自动设置tenant_id字段。对业务代码无侵入。

**Q：Spring AOP原理？**
A：基于动态代理。在方法执行前后插入额外逻辑，比如记录日志、事务管理。不用修改原方法代码。
